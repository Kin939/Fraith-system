# FRAITH.SYSTEM — Веб-портал D&D 5e кампании (Cloudflare Stack)

Полнофункциональный веб-портал для проведения D&D-кампании (**3 игрока + 1 мастер**), построенный на экосистеме **Cloudflare Pages + Workers (Hono) + D1 (SQLite) + R2 + Durable Objects (WebSocket Hibernation API)** с живой интеграцией **Long Story Short (LSS)** и кастомизируемой тёмной аниме-темой для каждого аккаунта.

---

## Архитектура

1. **Frontend (Cloudflare Pages + React 18 + TypeScript + Vite + Tailwind CSS)**: SPA с вкладками кампании (включая «Доску» на tldraw SDK), Zustand-стором и системой темизации на CSS-переменных (`--bg`, `--surface`, `--primary`, `--accent`, `--text`, `--text-muted`, `--border`, `--glow`).
2. **Backend API (`/functions/api/[[route]].ts` на Hono)**: единый роутер Cloudflare Pages Functions с проверкой JWT-сессий из `httpOnly` cookie (и опциональной поддержкой заголовков **Cloudflare Access / Zero Trust**) и строгим разделением прав `dm` и `player` (`playerId = 1, 2, 3`).
3. **Хранение данных (Cloudflare D1 + R2)**: все сущности (пользователи, темы аккаунтов, кэш LSS, личные журналы, квесты, бестиарий с серверной маскировкой неоткрытых существ, SRD/Homebrew-заклинания, дерево талантов и общий пул вдохновений) хранятся в SQLite на D1; иллюстрации загружаются в бакет R2 и раздаются через `/api/r2/:key`.
4. **Real-Time синхронизация (`workers/campaign-do.ts` — Durable Objects + WebSocket Hibernation API)**: один экземпляр `CampaignRoom` координирует всю кампанию, пробуждаясь при сообщениях и мгновенно рассылая изменения квестов, бестиария, заклинаний, талантов, вдохновений, тем и бросков кубиков LSS всем 4 участникам.
5. **Отдельный realtime-контур для «Доски» (`workers/board-do.ts` — Durable Object + WebSocket)**: один `BoardRoom` на каждую доску хранит документ холста в SQLite-хранилище DO, рассылает diff-патчи tldraw, presence, курсоры, комментарии, dot-voting и таймер сессии, не пересекаясь с `CampaignRoom`.
6. **Двухуровневая интеграция с Long Story Short (LSS)**:
   - Встраивание листа через `<iframe src="https://longstoryshort.app/iframe/characters/list/">` с `SHEET_IFRAME_SANDBOX` и `window.postMessage` мостом из официального `@longstoryshort/vtt-sdk` (`lss:roll`, `lss:manifest`, `dnd:health`) — строго в режиме чтения, без доступа к DOM iframe.
   - Серверный кэш и синхронизация `POST /api/player/:id/sync-lss` + периодический polling (`useLssSync`) и ручной импорт `.json` по схеме `https://longstoryshort.app/schema/v1/character.json` для полей вне `postMessage` (монеты, заметки, класс, лимит заклинаний).

## Аккаунты кампании

В системе предусмотрены 4 защищённых паролем аккаунта:
- `dm` — **Мастер (DM)** (отдельный секретный пароль; полный доступ ко всем вкладкам и вкладке «Мастер»).
- `player1`, `player2`, `player3` — **3 слота игроков** (индивидуальные пароли игроков просматриваются и меняются Мастером во вкладке **«Мастер» → «Пароли и доступы»**).

## Портреты персонажей и оформление плиток квестов

- **Аватар из листа персонажа.** Портрет берётся из `sheet.avatar` LSS-листа (или из `users.avatar_key`) и автоматически превращается в аватар автора в мессенджере, в цитатах ответов, в карточках отряда и в шапке листа персонажа. Портрет можно заменить вручную: `POST /api/profile/avatar` (multipart, поле `file`; Мастер может передать `playerId`), сброс — `DELETE /api/profile/avatar`.
- **Редактор плитки квеста.** Для каждого квеста хранятся `tile_accent`, `tile_emblem`, `tile_pattern` и `is_important`. В «Мастер» → «Квесты» есть панель оформления с предпросмотром: палитра акцентов + свой цвет, 10 HUD-эмблем, **34 узора фона** в шести категориях (Геометрия, Магия, Техно, Опасность, Природа, Чистые: сетка, точки, ромбы, гексы, шевроны, кольца, чертёж, плата, штрихкод, руны, звёзды, искры, аркана, туманность, сигил, пульс, скан, CRT, данные, прицел, полосы тревоги, пламя, трещины, чешуя, лозы, дерево, камень, волны и др.), готовые пресеты и метка «важно» (плитка получает свечение и бегущий блик и поднимается в начало списка). Быстрое переключение важности — `PATCH /api/dm/quests/:id/tile`.

## Пассивные проверки, оформление талантов и размер плиток

- **Пассивные проверки.** В блоке боевых плашек листа персонажа теперь три отдельных значения: **П. Восприятие**, **П. Анализ**, **П. Проницательность** (10 + модификатор навыка с учётом владения/компетентности и бонусов `passive.*`). Подпись показывает уровень владения, клик отправляет проверку навыка в лог бросков.
- **Оформление талантов.** У узлов дерева талантов те же декоративные поля, что и у квестов: `tile_accent`, `tile_emblem`, `tile_pattern`, `is_featured` (миграция `0006_talent_tile_style.sql`). В модалке «Мастер → Таланты» есть живой предпросмотр и панель оформления (палитра, эмблемы, узоры, метка «Ключевой»); ключевой талант получает свечение, бейдж `KEY` и поднимается в начало `GET /api/talents`. Быстрое переключение — `PATCH /api/dm/talents/:id/tile`.
- **Размер плиток.** Переключатель S / M / L / XL в шапке «Квестов» и «Талантов» (`src/lib/tileSize.ts`, хранится в `localStorage` на пользователя): меняет высоту и плотность широких карточек квестов, масштаб узлов дерева талантов (позиции сохраняются) и вид-сетку талантов.
- **Вид «Плитки» у талантов.** Кроме холста-дерева появился режим карточек с описанием, стоимостью, статусом открытия и фильтром «Ключевые».

## Заметки квестов и связи с NPC

- **Прямоугольные плитки квестов.** Квесты снова показаны широкими горизонтальными карточками: слева иллюстрация или эмблема, справа название, статус, метки «важно»/«риск» и сегментированный прогресс. Список идёт одной колонкой, поэтому плитка всегда остаётся прямоугольной; переключатель S/M/L/XL меняет её высоту и размер медиа-блока. Счётчик заметок выводится бейджем на плитке (`quest.notesCount`).
- **Заметки от лица автора — у квестов, НПС и существ.** Любой участник стола (и игрок, и Мастер) пишет заметку от своего лица; заметки видны всем. Каждая запись показывает портрет и имя автора: у игрока — имя персонажа («от лица персонажа · игрок …»), у Мастера — корона и «мастер кампании». Над полем ввода всегда видно, от чьего лица уйдёт следующая заметка. Свою можно отредактировать или удалить, Мастер — любую. Лента одна для всех сущностей (`src/components/common/EntityNotes.tsx`): квест → низ карточки, НПС → кнопка «Заметки» на карточке во вкладке «Связи», существо → низ карточки бестиария. API: `GET/POST /api/quests|npcs|bestiary/:id/notes`, `PUT/DELETE /api/notes/:noteId`; живые обновления — `notes:updated { kind, entityId, notes }`. Таблица `entity_notes` (`entity_type IN ('quest','npc','creature')`, миграция `0008_entity_notes_and_dndsu_bestiary.sql`), старые заметки из `quest_notes` переносятся автоматически при старте. Заметки к скрытым от игроков НПС и монстрам игроку недоступны (404), пока Мастер не откроет карточку. Ctrl/⌘+Enter отправляет, лимит 2000 символов.
- **Вкладка «Связи» перед «Деревом талантов».** Каталог NPC кампании: имя, роль, фракция, локация, отношение к отряду (дружелюбен / нейтрален / насторожен / враждебен / неизвестно), публичное описание и портрет. Мастер создаёт контакт **скрытым** — игроки его не видят вовсе, пока он не нажмёт «Открыть игрокам». У Мастера дополнительно есть тайные заметки (`secret_notes`), которые никогда не уходят игрокам, кнопки редактирования и удаления и фильтры «Все / Открытые / Скрытые». API: `GET /api/npcs` (игрокам — только открытые), `POST/PUT/DELETE /api/dm/npcs`, `PATCH /api/dm/npcs/:id/reveal`; живые обновления — `npcs:updated`. Таблица `campaign_npcs`.

## Бестиарий dnd.su: 2 984 существа, скрытые по умолчанию

- **Каталог.** `public/data/dndsu-bestiary.json` (13 МБ) собран из зеркала dnd.su: `key` (слаг), `dndsuId`, `name`, `nameEn`, `sourceTitle`, `size`, `type`, `alignment`, `ac`, `hp`, `hpNum`, `speed`, `senses`, `languages`, `cr`, `crNumeric`, `xp`, `environment`, `statblock` (черты, действия, описание), `url`, `imageUrl` / `imageFullUrl`. Дубли слаг-страниц схлопнуты по `data-id`, итог — 2 984 уникальных существа.
- **Опыт за монстра.** `xp` берётся прямо из строки «Опасность … (N опыта)» карточки dnd.su (2 934 существа), для остальных 50 без CR — из официальной таблицы опыта по CR. Опыт показывается на плитке («Опыт 1 800»), в шапке и блоке статов карточки, в списке редактора Мастера и редактируется вручную (колонка `bestiary.xp`).
- **Автоматический импорт.** При первом открытии «Бестиария» Мастером каталог заливается пачками по 120: `POST /api/dm/bestiary/import` (до 250 записей в пакете, только `dm`), прогресс в баннере, кнопка «Остановить»; статус — `GET /api/dm/bestiary/import-status` (`total / compendium / revealed`). Повторный импорт идемпотентен по `import_key` и **не сбрасывает** флаги открытия, портреты и правки Мастера.
- **Всё скрыто, пока Мастер не откроет.** Импортированные монстры создаются с `is_revealed = 0`. `PATCH /api/dm/bestiary/:id/reveal { isRevealed }` — открыть/скрыть (живое событие `bestiary:updated`); игрок получает в `GET /api/bestiary` только открытых существ, а скрытая карточка отдаёт 404 и в ленте заметок.
- **Список и деталь.** `GET /api/bestiary` — лёгкие записи без статблока (имя, тип, размер, CR, КД, хиты, источник, счётчик заметок); `GET /api/bestiary/:id` — полная запись со статблоком, чувствами, языками и ссылкой на dnd.su. В интерфейсе: поиск по имени/типу/источнику, фильтры по типу существа и вилке CR, у Мастера — фильтр «Открытые / Скрытые», сортировка «по опасности / по имени» и подгрузка по 48 карточек.
- **Картинки с dnd.su.** У 2 163 существ на dnd.su есть арт. В датасете для каждого лежит `imageUrl` (тамб `_s`) и `imageFullUrl` (полный скан) плюс `gallery` — **все** иллюстрации из галереи снизу страницы (3 782 изображения, в среднем 1.3 на существо, до 12). Плитка показывает круглый аватар существа, а в карточке снизу появляется **галерея dnd.su**: сетка миниатюр, по клику — лайтбокс с полным сканом, стрелками ←/→ и Esc. Если у существа нет иллюстраций (821 вид), на плитке рисуется монограмма с первой буквой имени, а в карточке галерея не показывается.
- **Загрузка арта.** `MonsterArt`/`DndsuImage` перебирают источники по очереди: загруженный Мастером портрет → прямой файл dnd.su (браузер обычно достаёт его даже там, где воркер не может) → `GET /api/media/dndsu/:file` (тот же домен, кэш в `caches.default` на год, `immutable`) → другое разрешение (тамб ↔ полный скан) → плейсхолдер. Поэтому одна недоступная картинка не ломает карточку.
- **Обновление каталога.** У строк каталога есть `compendium_version`; `GET /api/dm/bestiary/import-status` возвращает `stale` — сколько строк залито старой версией датасета (без опыта/арта/галерей). Мастер при открытии «Бестиария» видит баннер «Обновить каталог», и импорт запускается автоматически; повторный импорт не сбрасывает открытие монстров, заметки и загруженные портреты.
- **Схема.** В `bestiary` добавлены `name_en`, `size`, `alignment`, `source_title`, `source_url`, `import_key` (уникальный индекс), `is_compendium`, `speed`, `senses`, `languages`, `xp`, `image_url`, `image_full_url`, `gallery_json`, `compendium_version`; ручные существа Мастера живут в той же таблице с `is_compendium = 0`.

## Вкладка «Доска»: collaborative canvas на tldraw (клон Miro/SBoard, без ИИ)

Вкладка **«Доска»** стоит строго между «Мессенджером» и «Мастером». Остальные вкладки, их порядок и поведение не менялись.

**Холст.** Бесконечное полотно на **tldraw SDK 3.15** (`src/pages/BoardPage.tsx`, `src/components/board/*`): панорамирование (средняя кнопка мыши / Space+драг / колесо), зум колесом и пинчем, мини-карта, «вписать в экран», «приблизить к выделению», фон доски — точки / линии / клетки / чистый (в тёмной теме, движется вместе с зумом). Инструменты tldraw дают стикеры (цвет, размер, текст), фигуры (прямоугольник, эллипс, ромб, стрелка, линия; заливка, обводка, толщина, штрих/пунктир), текст (шрифт, размер, выравнивание), перо и маркер, точечный и полный ластик, фреймы (сворачиваются, двигают содержимое), коннекторы с привязкой к фигурам/стикерам, авто-роутингом и подписями, таблицы, документы и интеллект-карты — наборами фигур из библиотеки шаблонов.

**Шаблоны** (`src/components/board/boardTemplates.ts`): интеллект-карта, блок-схема, Kanban, вайрфрейм, ретроспектива, SWOT, карточка объекта, таблица, документ и D&D-набор — карта подземелья, трекер инициативы, карта мира. Мастер сохраняет текущее выделение как собственный шаблон (`board_templates`, общий или для конкретной доски) и удаляет их; игроки применяют шаблоны одним кликом. Кнопка «＋ узел» в шапке добавляет ветвь интеллект-карты с авто-размещением и связью.

**Realtime.** Каждая доска — отдельный Durable Object **`BoardRoom`** (`workers/board-do.ts`, миграция `v2`, биндинг `BOARD_ROOM`), поэтому тяжёлые правки холста не блокируют мессенджер/квесты (`CampaignRoom` живёт в своём DO). Клиентские изменения tldraw store уходят как diff-патчи `{added, updated, removed}` в WS, DO применяет их к документу в SQLite-хранилище и рассылает остальным. Presence, курсоры и выделения — **эфемерны** и на диск не пишутся: курсоры в цвете акцента из `user_themes` с плашкой имени, аватары присутствия в шапке. Авто-переподключение с экспоненциальной задержкой и **replay пропущенных патчей** по `lastSeq` (журнал на 400 записей), при обрезанном журнале — полный снапшот чанками. Комментарии (треды, привязка к объекту или точке, @mentions, «решено»), dot-voting (до 3 точек на объект) и общий таймер сессии хранятся в DO и видны всем участникам.

**Доски и права.** Несколько досок на кампанию: `GET/POST /api/boards`, `PATCH/DELETE /api/boards/:id`, `GET /api/boards/:id/ws`, `POST /api/boards/:id/upload`, `GET/POST /api/boards/:id/templates`, `DELETE /api/boards/:id/templates/:templateId`. Создавать, переименовывать и удалять доски может только Мастер; он же выдаёт каждому игроку `read` / `write` / без доступа (`board_access`). Игрок видит только разрешённые доски; на read-only доске инструменты tldraw заблокированы, патчи такого клиента DO игнорирует, а presence/курсоры доступны только участникам с доступом. Первая доска «Доска кампании» создаётся автоматически при первом открытии вкладки Мастером (всем игрокам — `write`).

**Экспорт.** PNG — `editor.toImage` (вся доска, scale ×2) и скачивание файла; PDF — тот же рендер в печатном окне браузера («Сохранить как PDF»), отдельная PDF-библиотека не подключается.

**Файлы и медиа.** Картинки/PDF/видео вставляются drag&drop, кнопкой и из буфера обмена: `POST /api/boards/:id/upload` (multipart, до 8 МБ) кладёт объект в R2 (или в D1-фолбэк, если R2 не подключён) и возвращает ссылку, которую tldraw сохраняет в ассет-записи документа.

### Лицензия tldraw (production)

SDK tldraw **требует ключ лицензии в production** (в dev/preview не нужен; без ключа SDK показывает watermark). Ключ передаётся только во фронтенд-сборку:

```bash
# .env.local (или переменные окружения сборки Cloudflare Pages)
VITE_TLDRAW_LICENSE_KEY=tldraw-license-key-...
```

`wrangler.toml` для этого менять не нужно: ключ читается Vite (`import.meta.env.VITE_TLDRAW_LICENSE_KEY`, см. `src/lib/boardConfig.ts`) и прокидывается в `<Tldraw licenseKey>`. Скрипт деплоя прокидывает секрет репозитория `TLDRAW_LICENSE_KEY` в `VITE_TLDRAW_LICENSE_KEY` при сборке (см. `.github/workflows/deploy.yml`).

### Что не реализуется 1:1 (и чем заменено)

| Miro/SBoard | В «Доске» |
| --- | --- |
| Presigned URL для прямой загрузки в R2 | Загрузка через воркер `POST /api/boards/:id/upload` (presign требует S3-ключей R2, которых нет в проекте); R2 опционален, есть D1-фолбэк |
| Нативный экспорт PDF | PNG-рендер в печатном окне → «Сохранить как PDF» |
| Таблица с объединением ячеек и ручками ресайза колонок | Шаблон таблицы из geo-фигур: ячейки редактируются как фигуры, размеры меняются штатными ручками |
| Превью ссылок (OG-карточки) | Штатный bookmark-шейп tldraw со ссылкой; unfurl-сервис не подключён (нет внешних запросов из воркера в этой сборке) |
| Воспроизведение видео | Видео вставляется как видео-ассет; воспроизведение зависит от Range-запросов `/api/chat/files/*` — при недоступности открывается как файл |
| Богатый документ с заголовками/списками в одном блоке | Документ = заголовок + текстовые блоки + стикер-список (rich text tldraw: жирный, курсив, код, ссылки) |
| Встроенный ИИ (Miro Assist) | Не реализуется по требованию задачи |

**Схема D1.** `boards(id, name, created_by, created_at, updated_at)`, `board_access(board_id, user_id, permission CHECK read|write, PK(board_id,user_id))`, `board_templates(id, board_id, name, content_json, created_by, created_at)` плюс `board_settings(board_id → background, grid_size)` для вида доски (миграция `migrations/0011_boards.sql`). Содержимое холста в D1 не дублируется — оно в DO.

## Вкладка «Бой»: конструктор боёв и трекер инициативы

Вкладка **«Бой»** стоит сразу после «Связей» и перед «Мастером»; порядок и поведение остальных вкладок не менялись.

**Конструктор (только Мастер).** Имя боя, таймер хода (по умолчанию выключен — вводится числом секунд) и состав: игроки берутся из ростера кампании (`GET /api/combats/members` — имя персонажа, класс, уровень и текущие HP из листа), существа — из **существующего** бестиария (`GET /api/combats/bestiary`, только чтение, ничего в таблице не меняется). Мобы добавляются пачками с числом экземпляров и нумерацией («Гоблин 1», «Гоблин 2»), у каждого есть переключатели **«скрыть HP/AC/стат-блок»** и **«скрыть имя»**. Инициатива вводится вручную и сортируется по убыванию. «Начать бой» переводит бой в `active`; бой можно поставить на паузу, завершить (`finished`, трекер становится read-only, история сохраняется) и сбросить обратно в `setup` с теми же участниками.

**Трекер.** Вертикальный список с неоновым выделением текущего хода, номером раунда и presence-аватарами. «Следующий ход» увеличивает раунд на переходе через круг, поправляет индекс, сбрасывает таймер и пишет `turn_start` в журнал; мастер может править инициативу прямо в бою — порядок пересортировывается, текущий участник сохраняется. Эффекты с длительностью в раундах уменьшаются на каждом новом раунде и автоматически снимаются на нуле (в журнал — `effect_removed`). Таймер по истечении **не переключает ход сам** — HUD пульсирует и подсвечивается красным, решение остаётся за мастером.

**5e-правила.** 14 стандартных состояний SRD с русскими подписями и описаниями, истощение 0–6 с послаблениями по уровням, спасброски от смерти 3/3 (0 HP → «повержен», стабилизация вручную), временные HP и правка AC. Скрытие от игроков трёхуровневое: `is_hidden_from_players` (нет HP/AC/стат-блока/заметок), `hide_name` («Неизвестное существо» + силуэт) и `monster_hp_visibility = hidden | bar | numbers` (глобальная настройка полосы HP у видимых мобов). Что нельзя автоматизировать по правилам (снятие эффекта по успешному спасброску, концентрация), интерфейс делает полуавтоматическим: чип эффекта с длительностью `until_save` виден и мастеру, и игроку, а снимает его мастер кнопкой «✕».

**Realtime.** Один Durable Object **`CombatRoom`** на бой (`workers/combat-do.ts`, биндинг `COMBAT_ROOM`, миграция `v3`), поэтому трекер не пересекается с `CampaignRoom` и `BoardRoom`. DO — источник истины: порядок инициативы, HP, эффекты, текущий ход, таймер; после каждого изменения состояние сохраняется в D1 и рассылается всем сокетам **отфильтрованным по роли** — игрок физически не получает HP/AC/статблоки скрытых существ и журнал мастера. Presence (аватары, роли) эфемерен; клиент переподключается с экспоненциальной задержкой и пингует каждые 25 с.

**API.** `GET/POST /api/combats`, `GET/PATCH/DELETE /api/combats/:id`, `POST /api/combats/:id/participants`, `PATCH/DELETE /api/combats/:id/participants/:pid`, `POST /api/combats/:id/effects`, `DELETE /api/combats/:id/effects/:eid`, `POST /api/combats/:id/next-turn|timer|death-saves|exhaustion`, `GET /api/combats/:id/log` (только Мастер), `GET /api/combats/:id/ws`. Справочники: `GET /api/combats/bestiary`, `/conditions`, `/members`.

**Схема D1** (`migrations/0013_combat.sql`): `combats`, `combat_participants`, `combat_effects`, `combat_log`.


## Деплой в Cloudflare Production (в один клик через Git / `npx wrangler deploy`)

Проект сконфигурирован под современный единый стек **Cloudflare Workers + Static Assets (`wrangler@4`)**:
- В `wrangler.toml` задан `[build] command = "npm run build"`, `[assets] directory = "./dist"`, автопровижининг D1 (`fraith-dnd-db`) без необходимости вручную указывать `database_id`, и встроенный класс `CampaignRoom` Durable Object (`workers/index.ts`).
- При первом старте воркер автоматически создаёт все таблицы в D1 и заполняет seed-данные (`src/lib/bootstrap.ts`), а загрузка иллюстраций прозрачно использует бакет R2 `BUCKET` (если подключён) либо резервную таблицу `media_blobs` в D1.

В настройках **Cloudflare Workers & Pages → Build configuration** достаточно стандартной команды:
```bash
npx wrangler deploy
```
(или локально: `npm run deploy`).

Для установки продакшен-секрета подписи JWT:
```bash
npx wrangler secret put JWT_SECRET
```

## Автодеплой через GitHub Actions (`.github/workflows/deploy.yml`)

В репозитории настроен CI/CD пайплайн:
1. В настройках репозитория GitHub (**Settings → Secrets and variables → Actions**) добавьте два секрета:
   - `CLOUDFLARE_API_TOKEN` — API-токен Cloudflare с правами на *Cloudflare Pages (Edit)*, *Workers Scripts (Edit)*, *D1 (Edit)* и *R2 (Edit)*.
   - `CLOUDFLARE_ACCOUNT_ID` — ваш Account ID из панели Cloudflare.
2. Убедитесь, что в `wrangler.toml` прописан реальный `database_id` вашей D1-базы `fraith-dnd-db`.
3. При каждом слиянии в `main` (или ручном запуске **Run workflow** во вкладке Actions) GitHub автоматически проверит типы, соберёт `dist`, обновит Durable Object, применит миграции D1 и задеплоит сайт на Cloudflare Pages.
